# Setup and first run

This guide covers running with Docker on **Ubuntu Desktop 22.04/24.04 x86-64 with a local monitor and an NVIDIA RTX GPU**.
Isaac Sim ships inside the container image, so you do not install it on the host.
The hardware we tested on and the scope of the fresh-checkout test are in [VERIFICATION.md](VERIFICATION.md).

## What is in this repository?

The simulation code, keyboard teleop for both robots, training data collection and export, policy running and evaluation code,
and the source assets for the robot, manikin, and T-shirt.
`build` downloads Isaac Sim and the Python packages, and `prepare` downloads extra textures and materials.
Downloaded assets are checked against hashes stored in the repository, and the runtime scene is generated by the included code.
You do not need a copy of anyone else's working folder.
You bring your own demonstrations and models.

## Requirements

- An NVIDIA RTX GPU with a compatible driver. We tested on an RTX 5080 16 GB with 64 GB RAM on Ubuntu 22.04.
- We recommend at least 32 GB RAM, a 16 GB-class GPU, and 100 GB of free SSD space. Long RGB-D recordings need more.
- Check NVIDIA's [Isaac Sim 6.0.1 requirements](https://docs.isaacsim.omniverse.nvidia.com/6.0.1/installation/requirements.html) and use a driver that supports your GPU.
- Internet access and admin rights to install packages.
- The GUI steps below are for a local Linux desktop. CPU-only machines, WSL, and remote-desktop GUIs are outside what this guide was tested on.

## 1. Basic tools and NVIDIA driver

```bash
sudo apt-get update
sudo apt-get install -y git curl ca-certificates gnupg python3 xauth util-linux unzip
nvidia-smi
```

If `nvidia-smi` is missing or fails, install a driver first using Ubuntu's Additional Drivers tool or the [NVIDIA driver guide](https://docs.nvidia.com/datacenter/tesla/driver-installation-guide/), then reboot.
Run the GUI from a desktop session with a monitor attached. Choosing "Ubuntu on Xorg" at login lets the Xauthority path work.

## 2. Docker Engine

If Docker is already installed, check that `docker run --rm hello-world` works.
For a new install, follow [Docker's Ubuntu guide](https://docs.docker.com/engine/install/ubuntu/). The usual commands are:

```bash
sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
  | sudo tee /etc/apt/keyrings/docker.asc >/dev/null
sudo chmod a+r /etc/apt/keyrings/docker.asc
. /etc/os-release
printf 'deb [arch=%s signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu %s stable\n' \
  "$(dpkg --print-architecture)" "$VERSION_CODENAME" \
  | sudo tee /etc/apt/sources.list.d/docker.list
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo usermod -aG docker "$USER"
```

Log out and back in so the group change takes effect, then:

```bash
docker run --rm hello-world
```

Run project commands as your normal user. Membership in the docker group grants broad privileges, so follow your admin's policy on shared machines.

## 3. NVIDIA Container Toolkit

Set up GPU access for Docker following the [official install guide](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html).

```bash
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey \
  | sudo gpg --dearmor --yes --output /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
curl -fsSL https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list \
  | sed 's|deb https://|deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://|g' \
  | sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
sudo apt-get update
sudo apt-get install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker
docker run --rm --gpus all ubuntu:24.04 nvidia-smi
```

The last command should list your GPU. Restarting Docker affects other running containers, so coordinate with your admin on shared machines.

## 4. Clone the repository

```bash
git clone \
  https://github.com/rirolab/PhyRC_2027_Challenge.git
cd PhyRC_2027_Challenge
./run.sh doctor
```

If Git asks you to authenticate, set up the GitHub CLI or SSH with your own account. Never copy someone else's token or key.

## 5. Build the environment

```bash
./run.sh build
./run.sh prepare
./run.sh smoke
```

- `build`: installs the pinned Isaac Sim 6.0.1 image and Python dependencies.
- `prepare`: downloads required assets and generates the runtime scene. Run it on first install and after pulling updates.
- `smoke`: loads the real scene and runs a short control check. It prints `PHYRC-SMOKE-PASS` on success.

You do not need to set any EULA environment variables yourself; the runner passes the variables the NVIDIA container requires.
You are still responsible for reading and following NVIDIA's [container guide](https://docs.isaacsim.omniverse.nvidia.com/6.0.1/installation/install_container.html),
[software license agreement](https://www.nvidia.com/en-us/agreements/enterprise-software/nvidia-software-license-agreement/),
and [privacy policy](https://www.nvidia.com/en-us/about-nvidia/privacy-policy/).
The way this project launches the container does not change NVIDIA's terms.
Asset sources and terms are listed in [THIRD_PARTY.md](../../THIRD_PARTY.md).

The first run can take a long time while images download and shaders compile.
In our empty-cache test, the first control check took several more minutes after the scene appeared, and the whole run passed after about 6 minutes.
Seeing the scene or an initialization message does not mean it is ready; wait for `PHYRC-SMOKE-PASS`. Do not swap in `latest` or another Isaac Sim version.
If NGC asks for authentication, run `docker login nvcr.io` with your own account as described by NVIDIA.

## 6. Teleop and data collection

```bash
./run.sh gui
./run.sh gui --training-record 1 --evaluate 1
```

Do not run these two at the same time; only one run per checkout is supported.
To finish collecting, press `ESC` in the viewport and wait for `[Dataset export] READY` in the terminal.

## Troubleshooting

| Symptom | What to check |
|---|---|
| Docker permission denied | Did you log out and back in after joining the docker group? |
| GPU not visible in the container | NVIDIA Container Toolkit and the GPU check command above |
| DISPLAY/Xauthority error | Local graphical session, running from a terminal in that session, xauth installed |
| Run prepare first | Did `./run.sh prepare` finish? |
| active prepare/run | Has the previous run exited? |
| Window closed but no HDF5 | Export may still be running. Wait for READY and check `capture.json` |
| complete=false | The run ended before a valid policy step finished. Collect again and quit with ESC |
| Teleop feels slower than the video | Videos and policy steps use simulation time, which can run slower than real time on your PC |

Inside the container, the host's `output/` is `/output/`, the repository is mounted read-only at `/project/`, and `scripts/` is `/scripts/`.
For example, the host file `output/checkpoints/policy.pt` is `/output/checkpoints/policy.pt` in container commands.
